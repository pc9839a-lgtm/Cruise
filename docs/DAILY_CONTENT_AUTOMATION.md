# 오케이크루즈 일일 SEO 콘텐츠 자동 발행 지침

## 목적
매일 1개씩 검색 유입과 실제 문의 가능성이 높은 크루즈 콘텐츠를 발행한다. 단순 글 개수 늘리기가 아니라 **검색 의도 충족 → 오케이크루즈 신뢰 형성 → 관련 콘텐츠 탐색/문의로 연결**되는 글만 발행한다.

## 실행 대상
- GitHub 저장소: `pc9839a-lgtm/Cruise`
- 기본 브랜치: `main`
- 콘텐츠 허브: `/blog/`
- 기준 도메인: `https://cruiseplay-dyt.pages.dev`
- 브랜드 표기: **오케이크루즈**

## 가장 중요한 저장 구조
이 저장소는 생성된 `/blog/<slug>/index.html`만 저장하는 구조가 아니다. `tools/build-blog.mjs`가 `blog/posts/*.html`을 원본으로 다시 블로그를 생성할 수 있다. 따라서 **완성 페이지 파일만 추가하면 향후 재빌드에서 사라질 수 있다.**

새 글을 발행할 때 반드시 아래 3가지를 모두 남긴다.
1. 원본 본문: `blog/posts/<slug>.html`
2. 현재 배포용 완성 페이지: `blog/<slug>/index.html`
3. 메타데이터: `content/blog-meta.json`의 `posts` 배열에 slug/category/title/summary/thumbnail_url/tag_text/published_at/updated_at/sort_order를 등록

기존 빌드 로직을 실행하거나 수정하는 경우 새 글 3요소가 모두 유지되는지 먼저 확인한다. `cleanupGeneratedBlog()`가 생성 페이지를 지울 수 있으므로 원본 없이 완성 페이지만 추가하는 것은 금지한다.

## 매일 반드시 지킬 실행 순서
1. `main`의 현재 `/blog/`, `blog/posts/`, `content/blog-meta.json`, `sitemap.xml`, 관련 미들웨어/빌드 로직을 먼저 읽는다.
2. 기존 제목·slug·핵심 키워드를 검색해 동일 주제 또는 검색 의도 중복 여부를 검사한다.
3. 웹에서 최신 검색 결과와 공식 자료를 조사한다. 가격·규정·일정·선사 정책·항구 정보처럼 변할 수 있는 사실은 반드시 당일 기준으로 검증한다.
4. 새 글 후보를 최소 5개 내부적으로 비교하고, 아래 우선순위가 가장 높은 주제 1개만 선택한다.
5. 선택 주제가 기존 글과 50% 이상 검색 의도가 겹치면 발행하지 말고 다른 주제로 교체한다.
6. 본문 원본을 `blog/posts/<slug>.html`에 작성한다. `<!doctype>`, `<html>`, `<head>`는 넣지 않고 본문 조각만 저장한다.
7. `content/blog-meta.json`에 새 메타데이터를 등록한다. 기존 항목은 훼손하지 않는다. `sort_order`는 최신 글이 최상단에 오도록 기존 최소값보다 더 작은 값으로 지정한다.
8. 완성 페이지 `/blog/<slug>/index.html`을 생성한다. 현재 템플릿/미들웨어 스타일을 깨지 말고 사용자 노출 브랜드는 오케이크루즈로 통일한다.
9. 블로그 목록 최상단에 새 글 카드가 보이게 하고 전체 글 개수를 정확히 +1 한다. 임시 숫자를 하드코딩할 경우 다음 실행에서 이전 글이 사라지지 않게 누적 구조인지 확인한다.
10. `sitemap.xml`에 새 canonical URL과 정확한 `lastmod`를 반영한다. RSS/Feed를 수동 관리하는 상태라면 새 글이 최신 피드에 포함되는지도 갱신한다.
11. 관련 기존 글 3~5개와 내부링크를 연결하되, 기존 글의 핵심 검색 의도를 훼손하지 않는다.
12. 모든 변경을 `main`에 커밋한다.
13. 마지막으로 새 URL, 목록 노출, 글 수, sitemap, 원본 소스 존재, noindex 여부를 다시 확인한다. 확인되지 않은 상태를 '배포 완료'라고 보고하지 않는다.

## 주제 우선순위
1. 구매 직전/문의 직전 검색어: 가격, 예약, 비교, 추천, 출발지, 일정, 선사/선박 비교
2. 목적지 검색어: 일본, 대만, 싱가포르, 지중해, 알래스카 등
3. 출발항 검색어: 부산 출발, 인천 출발, 해외 출발항 가이드
4. 선사/선박 검색어: MSC, 로얄캐리비안, 코스타, NCL 등 실제 수요가 있는 비교형 콘텐츠
5. 비용 절감 검색어: 예약 시기, 싼 달, 객실 선택, 항공 포함 총비용
6. 기존 정보성 클러스터를 강화하는 롱테일

정보성 FAQ만 연속으로 발행하지 않는다. 최근 3개 글 중 2개 이상이 FAQ형이면 다음 글은 가격·비교·목적지·선사·출발항 중 하나를 선택한다.

## 금지 사항
- 이미 있는 글의 제목만 바꿔 사실상 같은 내용을 재발행하지 않는다.
- 검색량/의도가 불분명한 잡학성 주제를 글 수 채우기용으로 만들지 않는다.
- 확인되지 않은 가격을 '현재 최저가'로 단정하지 않는다.
- 한 여행사/블로그 한 곳만 근거로 가격이나 정책을 일반화하지 않는다.
- 선사 규정, 비자, 세관, 팁, 취소 규정 등 변경 가능 정보는 과거 지식만으로 쓰지 않는다.
- 출처 없이 숫자를 만들지 않는다.
- `크루즈플레이`를 새 콘텐츠의 사용자 노출 브랜드명으로 사용하지 않는다. 사용자 노출 브랜드는 `오케이크루즈`로 통일한다.
- 기존 상업 페이지(`/membership/`, `/partner/`, `/academy/`)의 noindex 정책을 임의로 변경하지 않는다.
- SEO를 이유로 키워드를 부자연스럽게 반복하지 않는다.
- 원본 `blog/posts/<slug>.html` 없이 완성 페이지 하나만 추가하지 않는다.
- 기존 `content/blog-meta.json` 항목을 통째로 덮어쓰거나 삭제하지 않는다.

## 글 기본 SEO 규격
- 제목: 핵심 검색어를 앞쪽에 배치. 한국어로 자연스럽게, 클릭 이유가 명확해야 한다.
- H1: 페이지당 1개.
- 메타 description: 약 110~160자. 핵심 검색어 + 사용자가 얻는 답을 명확히.
- canonical: 자기 자신 URL.
- robots: `index,follow,max-image-preview:large,max-snippet:-1,max-video-preview:-1`.
- OG: locale/type/site_name/title/description/url/image 포함.
- Twitter: `summary_large_image`.
- 구조화 데이터: 기본 `BlogPosting` + `BreadcrumbList`; 실제 본문에 FAQ가 있으면 `FAQPage` 추가.
- `datePublished`, `dateModified`: `YYYY-MM-DDTHH:mm:ss+09:00` 형식.
- author: `오케이크루즈 편집팀`, URL은 `/about/`.
- publisher: `오케이크루즈`.
- 이미지 alt: 제목 복붙이 아니라 이미지의 의미 + 핵심 맥락으로 작성.

## 본문 품질 규격
- 첫 화면에서 바로 결론을 준다.
- 도입부는 2~4문단 이내. AI식 장황한 서론 금지.
- 표 또는 비교 블록을 최소 1개 사용한다.
- H2는 검색자가 실제로 묻는 순서로 구성한다.
- 변동 가능한 숫자는 기준 날짜와 조건을 함께 쓴다.
- 서로 다른 조건의 가격을 한 숫자로 뭉개지 않는다.
- 실제 선택 기준을 제시한다. 예: '가족/성수기/발코니 고정이면 조기예약', '날짜·선박·객실이 모두 유연하면 막판특가도 가능'.
- 관련 기존 콘텐츠 내부링크 3개 이상을 자연스럽게 배치한다.
- 외부 출처는 공식 선사/정부/항만/권위 있는 업계 자료를 우선한다.

## 키워드 카니벌라이제이션 기준
새 글을 쓰기 전에 반드시 기존 글과 비교한다.
- 같은 핵심 키워드 + 같은 사용자 질문이면 신규 글 금지.
- 상위 개념/하위 개념 관계면 역할을 분리한다.
  - `크루즈 여행 가격` = 기간별 실제 예산 비교
  - `크루즈 총비용` = 비용 항목의 구조 설명
  - `크루즈 예약 시기` = 언제 예약할지에 집중
- 겹치는 경우 기존 글 내부링크로 연결하고 각각의 메인 답을 명확히 다르게 유지한다.

## 발행 후 검증 체크
- 새 URL이 200 응답 가능한가
- `<title>`과 H1이 의도한 키워드와 일치하는가
- canonical이 자기 자신인가
- noindex가 붙지 않았는가
- `blog/posts/<slug>.html` 원본이 존재하는가
- `content/blog-meta.json`에 새 slug가 존재하는가
- 블로그 목록 최상단에 노출되는가
- 전체 글 수가 정확한가
- sitemap에 새 URL이 존재하는가
- 내부링크가 404가 아닌가
- 구조화 데이터 JSON 문법이 깨지지 않았는가
- 모바일에서 표/긴 URL이 화면을 넘치지 않는가

## 자동화의 최종 보고 형식
매 실행 후 사용자에게 길게 설명하지 말고 아래만 보고한다.
- 발행 제목
- 메인 키워드
- 신규 URL
- 근거로 확인한 핵심 최신 사실 2~3개
- 변경 커밋 SHA
- 원본/메타/목록/sitemap/라이브 검증 결과
